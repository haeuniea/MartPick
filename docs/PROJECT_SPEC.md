# MartPick(마트픽) 프로젝트 명세 (초안)

> 문서 상태: **초안** · 작성일 2026-09-29
>
> 표기 규칙
> - **[확인 필요]** 아직 결정하지 않은 정책. 개발자 결정 후 확정합니다.
> - **[검증 예정]** 실제 API 응답으로 확인하지 않은 사항. 1단계 API 검증 후 갱신합니다.

## 1. 프로젝트 개요

### 1-1. 서비스명

MartPick(마트픽)

### 1-2. 해결하려는 문제

생필품을 여러 개 구매할 때는 개별 상품의 최저가보다 **한 판매점에서 장바구니 전체를 구매할 때의 총액**이 중요합니다.
한국소비자원 참가격 서비스에서도 가격 비교 기능을 제공하지만, 개발자가 확인한 장바구니 비교 화면에서는 사용자가 비교할 판매점을 직접 선택해야 했습니다.
(기존 서비스에 유사한 기능이 전혀 없다고 단정하지 않습니다.)

### 1-3. 핵심 사용자 시나리오

**비회원**

1. 상품을 검색합니다.
2. 상품을 선택하고 수량을 설정해 장바구니에 담습니다.
3. 비교할 지역(시·도)을 선택합니다.
4. 장바구니 총액 비교를 요청합니다.
5. 선택 지역의 판매점별 총액을 확인합니다.

**회원**

1. 회원가입 후 아이디·비밀번호로 로그인합니다.
2. 상품을 장바구니에 담고 수량을 변경합니다. 장바구니는 계정에 저장됩니다.
3. 로그아웃 후 다시 로그인해도 기존 장바구니를 불러옵니다.
4. 저장된 장바구니로 판매점별 총액을 비교합니다.

### 1-4. 제공 가치

- 사용자가 판매점을 직접 고르지 않아도, 선택 지역의 판매점을 자동으로 찾아 장바구니 총액을 비교합니다.
- 가격이 모두 확인된 판매점만 순위에 포함해, 누락 가격 때문에 총액이 왜곡되지 않도록 합니다.
- 모든 가격에 조사일을 함께 표시해 데이터의 기준 시점을 분명히 합니다.

## 2. 기능 요구사항

### 2-1. 상품 검색

- 상품명으로 검색합니다. 비회원도 사용할 수 있습니다.
- 결과에 상품명과 규격을 표시합니다.
- 상품 ID를 기준으로 가격 데이터와 연결합니다.
- 결과가 없으면 안내 메시지를 표시합니다.
- **검색 대상은 가격 데이터를 수집한 상품으로 한정합니다.** 수집하지 않은 상품이 검색되어 비교 결과가 항상 비는 문제를 막기 위함입니다.
  화면에 "검색 가능한 상품은 수집된 일부 상품으로 제한됨"을 안내합니다.
- 검색 방식(부분 일치 등) **[제안]** 상품명 부분 일치
- 규격 정보의 출처(상품 정보 API 필드 또는 공통 코드 조인) **[검증 예정]**

### 2-2. 비회원 장바구니 (세션 저장)

- 서버 세션(HttpSession)에 상품 ID와 수량을 저장합니다.
- 상품 추가, 삭제, 수량 변경을 지원합니다.
- 상품별 수량은 **1~99의 정수**만 허용합니다. 화면과 서버 양쪽에서 검증합니다.
- 같은 상품을 다시 담으면 **기존 수량에 더합니다.**
  더한 결과가 99를 넘으면 99로 조용히 바꾸지 않고, 요청을 반영하지 않은 채 수량 제한을 안내합니다.
- 세션이 만료되거나 로그아웃으로 세션이 무효화되면 비회원 장바구니는 사라집니다.
- 로그인 시 비회원 장바구니를 회원 장바구니에 병합하지 않습니다(MVP 제외).

### 2-3. 회원가입·로그인·로그아웃

- 아이디와 비밀번호로 회원가입합니다.
  - 아이디: **영문·숫자 4~20자**, 중복 불가
  - 비밀번호: **최소 8자, 최대 72바이트**. 대문자·특수문자 포함은 강제하지 않습니다.
  - 필수 입력값을 서버에서 검증합니다.
  - 비밀번호는 BCrypt로 해싱해 저장합니다(평문 저장 금지).
  - 가입 성공 후 로그인 화면으로 이동합니다.
- Spring Security 세션 기반 인증을 사용합니다. JWT는 사용하지 않습니다.
- 로그인 성공 시 서비스 화면으로 이동합니다.
- 로그인 실패 시 오류 메시지를 표시하되, **아이디 존재 여부를 구분해 노출하지 않습니다.**
- 로그아웃 시 인증 세션을 종료합니다.
- Spring Security 기본 CSRF 보호를 유지합니다.

### 2-4. 회원 장바구니 (DB 저장)

- 로그인한 회원의 장바구니는 DB에 저장합니다. 담기·삭제·수량 변경 규칙은 비회원 장바구니와 같습니다.
- 재로그인 후에도 장바구니가 유지됩니다.
- 별도의 회원 장바구니 URL이나 마이페이지를 두지 않습니다. 장바구니 URL은 비회원·회원이 같고, 서버가 로그인 여부에 따라 저장소를 선택합니다.
  - 비회원은 자신의 세션 장바구니만 사용합니다.
  - 로그인한 회원은 자신의 DB 장바구니만 사용합니다.
- 회원 장바구니는 본인만 조회·수정할 수 있습니다.
  - URL에 사용자 ID를 포함하지 않고, 서버가 인증 정보의 회원 ID로만 장바구니를 조회·수정합니다. **[제안]**
- 접근 제한 테스트 대상
  - 비회원 요청이 회원의 DB 장바구니에 접근할 수 없는지
  - 회원 A가 회원 B의 장바구니에 접근할 수 없는지

### 2-5. 판매점별 장바구니 총액 비교

- 비회원도 사용할 수 있습니다.
- 사용자가 판매점을 선택하지 않아도, 선택 지역의 판매점을 자동으로 비교합니다.
- 결과에 판매점명, 주소, 총액, 상품별 가격, 조사일을 표시합니다. 기준 조사일은 화면에 명확히 표시합니다.
- 가격 비교 로직은 회원 인증 기능과 결합하지 않습니다. 비교 로직은 "상품 ID와 수량 목록"만 입력으로 받습니다.
- 계산 규칙은 3장을 따릅니다.
- 일부 상품 가격만 있는 판매점은 **순위와 별도의 영역**에서 안내합니다.
  - 확인된 상품 수와 누락된 상품을 표시합니다.
  - 총액이나 임의의 예상 금액은 표시하지 않습니다.
  - 실제 API 데이터에서 누락을 판별하는 방식 **[검증 예정]**

### 2-6. 시·도 단위 지역 필터링

- 지역은 **시·도 단위**로 선택합니다.
- 선택 지역에 속하지 않는 판매점은 비교 결과에서 제외합니다.
- 판매점 정보의 지역 필드명과 코드 체계, 공통 코드 API와의 매핑 **[검증 예정]**
- 수집 데이터에서 지역별로 비교 가능한 판매점이 실제로 존재하는지 **[검증 예정]**

## 3. 가격 비교 핵심 비즈니스 규칙

| # | 규칙 | 상태 |
|---|---|---|
| R1 | **동일한 조사일의 가격만 비교합니다.** 모든 판매점에 같은 조사일을 적용합니다. 초기 버전의 기준 조사일은 **2026-09-25로 고정**하며, 사용자가 조사일을 선택하는 기능은 두지 않습니다. 이후 다른 날짜의 데이터를 수집하더라도 서로 다른 조사일의 가격을 섞어 비교하지 않습니다. | 확정 |
| R2 | 동일한 상품 ID로 가격을 매칭합니다. | 확정 |
| R3 | 판매점별 총액 = Σ(상품 가격 × 수량) | 확정 |
| R4 | 장바구니의 **모든 상품 가격이 확인된 판매점만** 총액을 계산하고 순위에 포함합니다. 일부 상품 가격만 있는 판매점은 별도 영역에서 확인된 상품 수와 누락 상품만 안내하고, 총액·예상 금액은 표시하지 않습니다. | 확정 |
| R5 | 가격이 없는 상품을 **0원으로 처리하지 않습니다.** 가격이 없다는 이유만으로 품절이라고 표현하지 않습니다. | 확정 |
| R6 | 비교 가능한 판매점은 **총액 오름차순**으로 정렬합니다. 총액이 같으면 판매점 ID 오름차순으로 정렬합니다. | 확정 (ID 정렬을 숫자/문자열 중 무엇으로 할지는 ID 형식 **[검증 예정]**) |
| R7 | 선택 지역 외 판매점은 제외합니다. | 확정 |
| R8 | 본사 등 실제 구매 장소가 아닌 판매점은 제외합니다. 판별 기준은 **판매점명 패턴 + 개발자가 직접 확인한 제외 ID 목록**입니다. 규칙의 한계는 README에 명시합니다. | 확정 (패턴 문자열과 제외 ID 목록 **[검증 예정]**) |
| R9 | 조사일을 화면에 명시하고, 조사 가격이 **실시간 판매 가격·재고를 보장하지 않는다**는 문구를 표시합니다. | 확정 |
| R10 | API의 `Y/N` 필드는 명세를 확인하기 전까지 임의로 해석하지 않으며 계산에 사용하지 않습니다. | 확정 |
| R11 | 사용자별 장바구니 접근 권한은 서버에서 검증합니다. | 확정 |

추가 확인 사항

- 가격 필드가 정상가인지 할인가인지 **[검증 예정]**
- 본사 제외 규칙(R8)의 목적은 본사처럼 실제 구매 장소가 아닌 데이터만 제외하는 것입니다(예: 판매점 115 `세븐일레븐(본사)`). 판매점명 패턴과 수동 제외 ID가 실제 개별 매장을 잘못 제외하지 않는지 확인해야 합니다. **[검증 예정]**

## 4. 데이터 수집 및 관리

### 4-1. 데이터 출처

한국소비자원 생필품 가격 정보 API (`https://apis.data.go.kr/B551919/ProductPriceInfoService`)

| 오퍼레이션 | 용도 |
|---|---|
| `getProductInfoSvc.do` | 상품 정보 |
| `getStoreInfoSvc.do` | 판매점 정보 |
| `getProductPriceInfoSvc` | 가격 정보 (`goodInspectDay`, `entpId`, `goodId`; `entpId`·`goodId` 중 하나 필수) |
| `getStandardInfoSvc.do` | 공통 코드 정보 |

- 확인된 호출 제한: 2,000회/일
- 정확한 엔드포인트 경로, 응답 형식(XML/JSON), 페이징 파라미터, 필드 의미 **[검증 예정]**
- **API 호출 실패와 정상 호출의 빈 결과를 명확히 구분합니다.**
  - 호출 실패를 "가격 데이터 없음"으로 저장하거나 표시하지 않습니다.
  - 실패 시 원인을 확인할 수 있도록 처리하되, 인증키 등 민감정보를 로그에 남기지 않습니다.
  - 실패로 판단할 조건(HTTP 오류, API 오류 코드 등)과 오류 응답 형식 **[검증 예정]**

### 4-2. 저장 및 사용 방식

- 사용자 요청마다 외부 API를 호출하지 않습니다. **수집한 데이터를 PostgreSQL에 저장한 뒤** 비교에 사용합니다.
- 가격은 조사일과 함께 저장합니다. **판매점·상품·조사일 조합**은 중복 저장하지 않습니다(DB 유니크 제약).
- 수집 방식 **[제안]** 선정한 상품 ID별로 가격을 조회하는 방식. 호출 수가 상품 수에 비례해 호출 제한 내에서 운영할 수 있고, 모든 지역의 판매점 가격을 확보할 수 있습니다. 확정은 API 검증 이후입니다.
- 수집 실행 방법 **[제안]** 스케줄러 없이 개발자가 수동으로 1회 실행합니다.

### 4-3. 초기 수집 범위

- 상품 **5~10개**, 조사일 2026-09-25
- 먼저 상품 ID `1000`, `1003`, `1008`의 실제 상품명과 규격을 확인한 뒤 추가 상품을 선정합니다. **[검증 예정]**
- 제한된 데이터 범위는 화면과 README에 명시합니다.

### 4-4. 인증키 관리

- API 인증키는 환경변수(`DATA_GO_KR_SERVICE_KEY`)로 관리합니다.
- 소스코드, 테스트 코드, README, 협업 기록, 로그, Git에 실제 인증키를 포함하지 않습니다.

| 인증 | Spring Security, 세션 기반 인증, BCrypt |
| 로컬 실행 환경 | Docker Compose (PostgreSQL) |
| 테스트 | JUnit 5 (Testcontainers는 초기 제외, 실제 PostgreSQL 연동 테스트가 필요할 때 검토) |

- 단일 Spring Boot 애플리케이션으로 구성합니다. 별도 프론트엔드 프레임워크, 마이크로서비스, Redis, 메시지 큐는 사용하지 않습니다.
- Spring Boot 3.5.x의 OSS 지원은 2026-06-30에 종료되었습니다(spring.io 공식 자료 기준, 상용 지원은 2032-06-30까지). 프로젝트 요구사항에 따라 3.5.x를 유지하며, 이 사실을 README에 명시합니다.

## 6. 예외 및 경계 상황

| 상황 | 처리 방침 |
|---|---|
| 빈 장바구니로 비교 요청 | 비교를 수행하지 않고 "장바구니가 비어 있음"을 안내합니다. |
| 검색 결과가 없는 상품 | "검색 결과 없음"과 함께 검색 가능한 상품 범위가 제한되어 있음을 안내합니다. |
| 가격 정보가 누락된 상품 | 해당 상품 가격이 없는 판매점은 총액 순위에서 제외합니다. 0원으로 계산하지 않고, 품절로 표현하지 않습니다. |
| 선택 지역에 판매점이 없음 | 비교할 판매점이 없다는 사유를 안내합니다. |
| 선택 지역에 판매점은 있으나 장바구니 상품의 가격이 모두 있는 판매점이 없음 | 비교 가능한 판매점이 없다는 사유를 안내합니다. (판매점 없음과 구분) 일부 상품 가격만 있는 판매점은 별도 영역에 확인된 상품 수와 누락 상품을 표시합니다. |
| 잘못된 수량(0, 음수, 100 이상, 정수가 아닌 값) | 요청을 거부하고 오류 메시지를 표시합니다. 화면과 서버 양쪽에서 검증합니다. |
| 같은 상품 재추가로 합계 수량이 99 초과 | 99로 조정하지 않고 요청을 반영하지 않으며, 수량 제한을 안내합니다. |
| 로그인 실패 | 아이디가 없는 경우와 비밀번호가 틀린 경우를 구분하지 않는 동일한 메시지를 표시합니다. |
| 비회원과 회원의 장바구니 저장 방식 차이 | 비회원은 세션(세션 종료 시 소멸), 회원은 DB(재로그인 후 유지). 로그인 시 병합하지 않으므로, 로그인 전에 담은 비회원 장바구니는 회원 장바구니에 나타나지 않습니다. |
| 다른 회원의 장바구니 접근 시도 | 서버가 인증된 회원 ID로만 장바구니를 조회·수정하므로 접근할 수 없습니다. 비회원 요청도 DB 장바구니에 접근할 수 없습니다. |
| 수집 중 API 호출 실패 | 정상적인 빈 응답과 구분하며, "가격 데이터 없음"으로 저장·표시하지 않습니다. 민감정보 없이 원인을 기록합니다. (4-1 참조) |
