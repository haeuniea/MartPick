## 1. 공통 응답 형식

| 항목 | 관찰 결과 | 확인 범위 |
|---|---|---|
| 응답 형식 | XML | 4개 API 모두 |
| `_type=json` | 무시되고 XML 반환 | **상품 API에서만** 시험 |
| Content-Type | XML임에도 `text/html; charset=UTF-8` | 4개 API의 HTTP 200 응답 모두 |
| 루트 구조 | `<response>` 아래 `result`, `resultCode`, `resultMsg` | 4개 API 모두 |
| 페이징 파라미터 | `numOfRows=10&pageNo=2`를 지정해도 파라미터 없이 호출한 응답과 같은 결과 반환: 상품 604건, 판매점 630건(첫·마지막 ID 786·2227, 310,247바이트 동일), 가격 419행(상품 1000·2026-09-25, 첫·마지막 ID 887·1801, 114,050바이트 동일) | 상품·판매점·가격 API 각 1회 시험 |
| 공통 코드 API의 페이징 | **[미검증]** 페이징 파라미터를 시험하지 않음. 파라미터 없이(`classCode=AR`) 호출했을 때 311건이 한 번에 반환됨 | 1회 관찰 |
| 한 번에 반환되는 건수 | 파라미터 없이 호출했을 때 조건에 맞는 결과가 한 번의 응답으로 반환됨 (최대 관찰치: 판매점 630건, 가격 약 420행) | 관찰한 호출에 한함 |
| 페이징 정보 필드 | 응답에 `totalCount`, `pageNo` 등 페이징 정보 없음 | 관찰한 모든 응답 |
| 반환 건수 상한 | **[미검증]** 관찰치보다 많은 결과에서 잘리는지 알 수 없음 | — |

- 추론(미확인): 상품·판매점·가격 API는 `numOfRows`·`pageNo`를 지원하지 않거나 무시하는 것으로 보입니다. 시험한 값은 `numOfRows=10&pageNo=2` 한 조합뿐이므로, 다른 값이나 다른 파라미터 이름의 동작은 확인하지 않았습니다.
| 항목 요소 이름 | API마다 다름: 상품 `item`, 판매점 `iros.openapi.service.vo.entpInfoVO`, 가격 `iros.openapi.service.vo.goodPriceVO`, 공통 코드 `iros.openapi.service.vo.stdInfoVO` | 4개 API |

### 3-3. 광주·전남 판매점의 같은 이름·다른 ID 등록

- `021800000`(전남광주통합특별시) 판매점은 15곳(ID 2220~2235, 2231 없음)입니다. 이 중 **14곳**은 옛 코드(`020200000`/`021200000`)에 **같은 판매점명·다른 판매점 ID**의 판매점이 등록되어 있습니다. 2228 신세계백화점광주신세계점은 옛 코드에 같은 이름의 판매점이 없습니다.
- 같은 이름의 ID 쌍 예: 이마트광주점 1861 / 2223, 이마트광산점 882 / 2222, 롯데슈퍼문흥점 383 / 2220
- 판매점명만 같은지 비교했으며, 같은 이름의 두 ID가 **동일한 물리적 매장인지는 [미검증]**입니다(주소·좌표 등 다른 속성은 대조하지 않았습니다).
- 새 코드 판매점 15곳의 `areaDetailCode`는 옛 시·군·구 코드(`0202…`, `0212…`)를 그대로 사용해, 이 15건만 시·도 코드와 시·군·구 코드의 앞자리가 일치하지 않습니다.
- 그 외 같은 이름의 판매점: GS더프레시여의도점(1800, 1886), GS더프레시청주율량점(1761, 1885), GS더프레시평택이충점(1783, 1884) — 같은 시·도 안의 다른 ID. 의미 **[미검증]**
- 가격 데이터 현황은 6-5 참조.

## 5. 가격 정보 API (`getProductPriceInfoSvc`)

- 경로: **`.do`가 붙지 않습니다.** `getProductPriceInfoSvc.do`로 호출하면 HTTP 400.
- 요청 파라미터: `goodInspectDay`(YYYYMMDD)와 `entpId`·`goodId` 중 하나 이상. 둘 다 없으면 `resultCode=05`(7장).
- 응답 크기
  - `goodId` + 조사일 조회: 1회 약 265~421행 (상품 1000 기준 419행, 약 114KB)
  - `entpId` + 조사일 조회: 판매점 887 기준 334행 (약 90KB)
- 필드 (조회한 9개 상품, 3,492행 기준)

| 필드 | 존재 | 관찰 결과 |
|---|---|---|
| `goodInspectDay` | 전부 | `YYYYMMDD` 문자열 (예: `20260925`) |
| `entpId` | 전부 | 판매점 ID. 10자리 ID 3개 포함 |
| `goodId` | 전부 | 상품 ID(`goodId`)로 조회한 응답 9건에는 요청한 상품 ID만 포함. 판매점 ID(`entpId`)로 조회한 응답(887)에는 여러 상품 ID가 포함되며(334행), `entpId`는 요청한 판매점만 포함 |
| `goodPrice` | 전부 | 모두 숫자, 0원·빈 값 없음 |
| `inputDttm` | 전부 | `2026-09-23 10:56:09` ~ `2026-09-23 14:06:47` (상품 1000·1003·1008 기준). 조사일보다 이틀 앞섬. 의미 **[미검증]** |
| `goodDcYn` | 일부 | 원래 값: `Y` 249, `N` 8 (상품 1000·1003·1008 기준). 의미 **[미검증]** |
| `goodDcStartDay`, `goodDcEndDay` | `goodDcYn=Y`인 행 | 의미 **[미검증]** |
| `plusoneYn` | 일부 | 원래 값: `N` 8 (상품 1000·1003·1008 기준). 의미 **[미검증]** |

- `goodPrice`가 정상가인지 할인가인지, 할인 필드가 가격에 반영되는지 **[미검증]**
- 연결성: 가격 행의 `goodId`는 모두 상품 목록에, `entpId`는 모두 판매점 목록에 존재했습니다(연결 누락 0건).
- 같은 (판매점, 상품, 조사일) 조합의 중복: 3,492행 중 0건.

## 6. 기준 조사일(2026-09-25)과 비교 가능성

### 6-1. 조사일

- 조회한 9개 상품 3,492행과 판매점 887의 334행이 모두 `20260925`였으며, 다른 조사일이 섞여 반환되지 않았습니다.
- 가격을 조사하지 않은 날짜 `20260924`(상품 1000)로 조회하면 다른 날짜로 대체되지 않고 빈 결과(`resultCode=00`, `<result/>`)가 반환되었습니다.

### 6-2. 가격 누락의 표현

- 조회한 3,492행에 0원이나 빈 가격은 없었고, 가격이 없는 (판매점, 상품, 조사일) 조합은 **행 자체가 없었습니다.**
- 상품 1000·1003·1008 기준: 가격이 있는 판매점 424곳 중 3개 모두 있는 판매점 413곳, 일부만 있는 판매점 11곳.
  - 예: 926 이마트여의도점(1003 없음), 2228 신세계백화점광주신세계점(1000만 있음), 151 신세계백화점죽전점(1003만 있음)

## 11. 미검증 사항

- 가격 API의 `inputDttm`, `goodDcYn`, `goodDcStartDay`, `goodDcEndDay`, `plusoneYn`의 의미와, `goodPrice`가 정상가인지 할인가인지
- `(본사)` 판매점 가격의 성격 (전국 공통 가격·권장 가격·본사 직접 판매 가격 여부)
- 단위 코드 ME·LO·M0·MR·DA·MA, 업태 코드 SM·LM·DP·CS의 공식 명칭과 해당 `classCode`
- 공통 코드 API의 페이징 파라미터 동작, 모든 API의 반환 건수 상한 (상품 목록이 604건보다 많을 때 잘리는지 포함, 9-1)
- 판매점 기준 가격 조회와 상품 기준 가격 조회가 판매점의 전체 상품 범위에서 일치하는지: 판매점 3곳은 일치 확인(10-3), 나머지 판매점은 미확인
- 기준 조사일 가격이 0건인 상품 21개의 원인 (10-2)
- 같은 조사일을 다시 수집할 때 생기는 자연 변동 폭 (G1·G2 80% 임계값 재검토 근거)
- `_type=json` 등 형식 파라미터의 상품 API 외 동작
- API 전체 오류 코드 목록 (확인된 것: HTTP 400·401, `resultCode` `01`·`05`)
- 광주·전남에서 옛 코드와 새 코드에 같은 이름으로 등록된 14쌍, 같은 시·도 안 같은 이름 판매점(GS더프레시 3쌍)이 동일한 물리적 매장인지 여부
- 동점이 체인 공통 가격에서 비롯되는지 여부
